## General principles

- Show a reward's cause, rarity, and result once. Large artwork identifies the reward; small symbols identify its resource amounts. Aggregate repeated causes from committed facts without changing rewards or the economy.
- Use the same visual hierarchy and vocabulary for comparable rewards in the reviewer, session summary, and sync summary. Headers identify the category, badges identify rarity or Full Bloom, and supporting text explains the result.
- Keep primary totals and actions stable. Disclosure belongs next to the content it controls; rewards and plant journeys remain visible in the main scrollable list, while supplementary details start collapsed. Routine updates use reserved compact space, while unusual content expands on demand.
- Make actions visibly clickable and confine hover states to their targets. Both HUD sizes use the same drag behavior. Tooltips add missing information instead of repeating readable text.
- Reuse an existing item or reward asset before generating another illustration. The same committed identity uses the same asset across all three reward views.
- Design artwork at its actual display size. Use clear silhouettes, distinct subject art, intact transparency, and the existing Garden palette. Validate actual isolated-Anki rendering rather than trusting development previews.
- Layout measurement must match the real viewport. Verify narrow widths, long copy, scroll behavior, and state changes together so spacing and pinned regions do not drift.
